# Модуль ревʼю — коментарі прямо на сторінці

У прототип вбудований [comment-layer 1.2.0](https://github.com/neodisa/CommentLayer).
Рецензент натискає **💬** справа внизу, клікає по будь-якому елементу сторінки й
лишає коментар. Зʼявляється пін із номером, коментар прив'язується до самого
елемента, а не до координат.

Файли лежать у `comments/` у корені проєкту. Якщо надсилаєте прототип клієнту —
**надсилайте папку цілком**. Без неї сторінки працюють як звичайно, просто без
коментарів: ініціалізація захищена перевіркою.

---

## Режим за замовчуванням: локальний

Нічого налаштовувати не треба. Коментарі зберігаються в `localStorage` браузера
рецензента. Підходить, коли дивиться одна людина й потім віддає висновки текстом.

Обмеження очевидне: інший браузер або інший компʼютер цих коментарів не побачить.

---

## Спільний режим: Supabase

Потрібен, коли прототип дивляться кілька людей і всі мають бачити коментарі
одне одного в реальному часі. Займає близько десяти хвилин.

### 1. Проєкт

Зареєструватись на [supabase.com](https://supabase.com), створити **New project**.
Регіон краще EU. Пароль бази зберегти.

### 2. Таблиця

**SQL Editor → New query**, вставити вміст `comments/schema.sql`
цілком, натиснути **Run**. У **Table Editor** має зʼявитись таблиця `comments`.

### 3. Ключі

**Project Settings → API**, скопіювати:

- **Project URL** — вигляду `https://xxxx.supabase.co`
- **anon public key** — довгий рядок, що починається з `eyJ` або `sb_publishable_`

Ключ `anon` безпечно тримати у фронтенді — доступ обмежує RLS.

### 4. Підключення

У кожному HTML розкоментувати два рядки перед `assets/js/comments.js` — вони вже є у файлах, лише закоментовані:

```html
<script src="https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2"></script>
<script src="comments/supabase-adapter.min.js"></script>
```

Далі один раз вписати ключі в `assets/js/comments.js`:

```js
var SUPABASE={url:'https://xxxx.supabase.co', anonKey:'eyJ…'};
```

Більше нічого міняти не треба — ініціалізація сама перемкнеться на спільний
режим. Якщо Supabase раптом недоступний, віджет тихо повернеться до локального
сховища замість того, щоб не запуститися.

### 5. Перевірка

1. Відкрити прототип у двох вікнах — звичайному та інкогніто, з різними іменами.
2. Коментар з одного вікна має зʼявитись у другому за секунду-дві.
3. Видалення в одному вікні має прибрати пін у другому.
4. Вимкнути інтернет, додати коментар, увімкнути — він досинхронізується.

---

## Як віддати коментарі в роботу

У репозиторії модуля є `scripts/export-comments.mjs`. Запуск:

```bash
SUPABASE_URL=… SUPABASE_KEY=… node scripts/export-comments.mjs naxcon-wireframe-v2 open
```

Отримаєте Markdown зі списком змін: текст коментаря, сторінка, елемент, HTML і
скриншот. Цей файл можна віддати виконавцю або AI — він самодостатній.

---

## Що варто знати

**Політики доступу відкриті.** У схемі стоїть `using (true)`: будь-хто з
ключем читає й пише всі коментарі. Для внутрішнього ревʼю цього досить, для
публічного доступу потрібна справжня автентифікація.

**Ідентичність — це просто імʼя**, яке людина вписує сама. Не автентифікація.

**Прив'язка до сторінки враховує адресу.** У версії 1.2.0 коментар привʼязаний
до `pathname + hash`, тож коментарі різних сторінок не змішуються.

**`regenerated()` не викликається автоматично.** Ця функція призначена для нової
збірки: вона закриває коментарі, чиї елементи зникли. Викликати її варто лише
після того, як правки внесені й прототип перезібраний.
