# Деплой

Сайт статичний: жодної збірки, залежностей і серверної частини. Досить віддати
файли будь-яким хостингом.

## Vercel

1. **Add New → Project**, підключити репозиторій.
2. Framework Preset — **Other**. Build Command і Output Directory лишити порожніми.
3. Deploy.

`index.html` лежить у корені, тож Vercel віддасть його на домені без будь-яких
налаштувань. `vercel.json` додає лише зручності:

- короткі адреси: `/products` веде на `/internal/products`;
- `cleanUrls` — можна без `.html`;
- заборона індексації заголовком `X-Robots-Tag: noindex, nofollow`.

## Про регістр імен файлів

Головний файл має називатися `index.html` **рівно малими літерами**. macOS не
розрізняє регістр і показує `Index.html` як робочий, а Linux на Vercel
розрізняє: `Index.html` не вважається індексом теки й дає 404 на корені.

Перейменувати регістр на macOS можна лише через проміжне імʼя:

```bash
mv Index.html tmp.html && mv tmp.html index.html
```

## Будь-який інший хостинг

Скопіювати вміст репозиторію на сервер — структура вже готова: `index.html` у
корені, решта сторінок в `internal/`, ресурси в `assets/`.

Якщо сторінки відкриваються прямо з диска (`file://`), працює все, крім
спільного режиму коментарів — для нього потрібен `https`.

## Що не слід публікувати відкрито

Прототип містить справжні назви продуктів і напрямів. Заголовок `noindex` не
захищає від переходу за посиланням — якщо потрібне закриття, вмикайте на Vercel
**Deployment Protection** (Password або Vercel Authentication).
